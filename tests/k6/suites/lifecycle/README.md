# Жизненный цикл

Набор `lifecycle` проверяет, что конфигурация и история переживают перезапуск сервисов или обновление версии.
Он выполняется в два этапа с одним `RUN_ID`: `prepare` создаёт конфигурацию и историю, затем сервисы
перезапускаются или переключаются на другую версию без удаления данных, `verify` проверяет решения, ничего не меняя.

Доступность кейса определяется по функциональностям версии, на которой шла подготовка (`FROM_FEATURES`).

| ID | Подготовка | Проверка после перезапуска / обновления |
| --- | --- | --- |
| LC-01 | шаблон `amount() >= 100000 -> decline` на party+shop | 150000 — `fatal`, 5000 — `low` |
| LC-02 | группа с шаблоном `decline` на party | `fatal` |
| LC-03 | шаблон `inBlackList("card_token")` и строка чёрного списка | карта из списка — `fatal`, другая — `low` |
| LC-04 | `count("card_token", 30, days, "party_id") > 2` и 3 платежа в истории | `fatal` по истории в ClickHouse |
| LC-05 | (до `payouts`) шаблон `isTrusted(paymentsConditions(...))` + `big: amount() >= 100000 -> decline` | наблюдения: шаблон остаётся в management; решение для 150000 |
| LC-06 | (нужна `payouts`) шаблон и строка чёрного списка выплат | карта из списка — `fatal`, другая — `low` |

LC-05 показывает, что происходит с сохранённым шаблоном, синтаксис которого снят: остаётся ли он в management
и какое решение дают его остальные правила.

```bash
scripts/run-k6.sh lifecycle <версия>
scripts/run-k6.sh lifecycle <версия подготовки> <версия проверки>
```
